---
title: "Migrate from Claude Cowork"
description: "Move your files, skills, plugins and MCP servers to Harness."
---

You do not need to rebuild your setup to move from Claude Cowork to Harness. Start with one real task, bring over the capabilities it needs, and keep Cowork available until that task works end to end.

## What carries over

| From Claude Cowork | In Harness | What to do |
| --- | --- | --- |
| Local files and folders | Workspace files | Open the same folder or repository as a Harness workspace. |
| `SKILL.md` skills | Skills | Copy the skill folder into your workspace or install it as a plugin. |
| Claude-compatible plugins | Plugins | Import the plugin or marketplace manifest; Harness normalizes its skills, commands, and MCP dependencies. |
| MCP servers | Connectors and custom apps | Reconnect the server through Harness Connect or add its URL as a custom app. |
| Claude models | Anthropic provider | Add your Anthropic API key; Harness keeps it encrypted with your OS keychain. |
| Scheduled tasks | Scheduled tasks | Recreate each schedule and verify its workspace, permissions, and output location. |

<Note>
  Conversation history does not transfer automatically. Keep any important instructions in workspace files or skills rather than relying on an old thread.
</Note>

## 1. Install Harness and open the same work

1. [Download Harness](https://github.com/vaishnavjai/harness/releases) for macOS, Windows, or Linux.
2. Create a workspace from the folder or repository you used with Cowork.
3. Ask Harness to summarize the workspace before changing anything. This confirms it can read the files you expect.

Your files stay where they already are. Harness does not require you to upload a duplicate copy before you can work with them.

## 2. Choose your models

Harness is model-agnostic and reaches only the model endpoints you configure. You can keep using Anthropic models, add another provider, or run a model on your own computer.

- To keep using Claude, follow [Add an Anthropic API key](/start-here/connect-your-stack/add-anthropic-api-key).
- To use ChatGPT, follow [Sign in with ChatGPT](/start-here/connect-your-stack/sign-in-with-chatgpt).
- For another provider, your own API key, or an AI gateway such as OpenRouter or LiteLLM, follow [Add a custom LLM or AI gateway](/start-here/connect-your-stack/add-a-custom-llm).
- To run a model on your own computer, follow [Use local models (Ollama, LM Studio)](/start-here/connect-your-stack/use-local-models).
- For Gemini or Google Vertex AI, follow [Use Gemini and Google Vertex AI](/start-here/connect-your-stack/use-gemini-and-vertex-ai).

Your Claude subscription and Anthropic API billing may be separate. Confirm API access before removing Cowork from your workflow.

## 3. Bring over skills and plugins

Harness uses the same `SKILL.md` format. Copy a skill directory into the workspace, or import the plugin that contains it.

After importing each skill:

1. Open the skill and check any file paths, app names, or environment variables.
2. Run the smallest task that should trigger it.
3. Confirm the output before importing the next skill.

See [Connectors, skills, and plugins](/start-here/do-work-with-it/skills-plugins-and-mcp) for how Harness organizes these pieces.

## 4. Reconnect apps and MCP servers

Credentials do not move between products. Reconnect each service so Harness receives its own authorized access.

- For Gmail, Calendar, Drive, Slack, Notion, Linear, or any other remote or local MCP server, use [Add a custom MCP server](/start-here/connect-your-stack/add-an-mcp-server).

Test read-only actions first. Then test actions that modify data, such as sending a message or updating a record, with a disposable example.

## 5. Recreate schedules and browser tasks

For every recurring task, record:

- the prompt;
- its schedule and time zone;
- the workspace and files it can use;
- the connected apps it needs;
- where the result should be saved or sent.

Recreate one schedule at a time and run it manually before enabling recurrence. For browser-driven work, follow [Control the browser](/start-here/do-work-with-it/control-the-browser) and verify the target site while you are present.

## Cutover checklist

- [ ] The same workspace opens and the agent can read the expected files.
- [ ] At least one model is connected and billing is understood.
- [ ] Each required skill triggers on a representative task.
- [ ] Each connector or MCP server is authorized and tested.
- [ ] Scheduled and browser tasks have been run manually once.
- [ ] Important Cowork instructions are saved in files or skills.
- [ ] Cowork remains available until the representative workflow passes in Harness.

Once the checklist passes, make Harness the default for that workflow and migrate the next one.
