---
title: "Outbound network access"
description: "Which hosts Harness contacts, when, and how to see every request it made."
---

Harness is local-first. Out of the box it makes **no request to any host you did not configure**: no analytics, no crash reporting, no update checks, no remote model catalog, no favicon or icon CDNs. The machine-readable source for everything below is [`docs/enterprise/outbound-access.json`](https://github.com/vaishnavjai/harness/blob/main/docs/enterprise/outbound-access.json); CI checks it against the code with `node scripts/check-outbound-access.mjs`.

## What runs on your machine only

| Component | Where it listens | Notes |
| --- | --- | --- |
| Harness server | `127.0.0.1`, random port | Local API for the app. |
| Agent engine (OpenCode) | `127.0.0.1`, random port | Started with self-update, model-catalog fetch, default-plugin install and language-server downloads turned off. Public session sharing is disabled. |
| Memory engine (Hindsight) | `127.0.0.1:8888` by default | Bearer token per launch. A Python-level egress guard lets it reach only loopback and the model endpoints you configure. Data lives in `~/.config/harness/data/`. |

## Where your prompts and memories go

Only to the model providers you set up yourself:

- **Local models** (Ollama, vLLM, llama.cpp, LM Studio) at an address such as `http://127.0.0.1:11434/v1`: nothing leaves the machine.
- **Hosted providers** you add with an API key (`api.openai.com`, `api.anthropic.com`, `openrouter.ai`, …): prompts go to that provider only. Keys are kept in your OS keychain.

The hosted OpenCode Zen models are not offered, because nobody configured them.

## Opt-in destinations

These hosts are contacted only after you turn the matching feature on or act on it:

| Host | When | Turned on by |
| --- | --- | --- |
| `github.com`, `release-assets.githubusercontent.com`, `objects.githubusercontent.com` | Desktop update checks and downloads | **Settings → Updates** (off by default) |
| `registry.npmjs.org` | Self-hosted server update check | `HARNESS_UPDATE_CHECK=1` |
| `opencode.ai` | Guided engine install when the bundled engine is missing | Clicking **Install** |
| `api.github.com`, `raw.githubusercontent.com` | Importing a plugin or skill from GitHub | Starting the import |
| `mcp.notion.com`, `mcp.linear.app`, `mcp.sentry.dev`, `mcp.stripe.com`, `mcp.context7.com`, `mcp.slack.com`, or any MCP URL you enter | MCP connections | Adding that connection |
| `www.google.com` | New tab in the built-in browser panel | Opening a browser tab |

Links such as documentation or `ollama.com` open in your own browser and are never fetched by Harness.

## Enforcement and audit

- The app window never loads remote images, fonts, scripts, stylesheets, frames or beacons. Remote images in agent output are blocked rather than fetched.
- Every remote host Harness contacts is written once per launch to the audit log (`~/.config/harness/audit.log`) as `network.egress`, and every blocked load as `network.blocked`. Open **Settings → Audit log** to review them; the log is hash-chained, so **Verify now** detects removed or edited records.

## Locked-down networks

Because nothing is required by default, Harness runs fully offline with local models. If you want update checks behind a proxy, allow the three GitHub hosts above; everything else is per-feature.
